Full Pipeline

im_workflow\scripts\run_workflow.R

Located at C:\Users\TOURE\Documents\im_workflow. One orchestrator, run_workflow.R, runs all six steps in order and writes one row per run to logs\run_history.csv, whether it finishes or hard-stops partway through.

01One-command run

Git Bash / cmd — from the project root
$ cd C:\Users\TOURE\Documents\im_workflow
$ Rscript scripts\run_workflow.R

Or double-click run_workflow.bat — identical command, run from a window that stays open and pauses at the end so you can read the summary.

Step 5 runs three scripts in a fixed order: the Intelligence Engine first (its output tables feed the next one), then the Advocacy Report, then the Deck.

hard stop Step 2 is the only one that can kill the run

If regional_im_repository_builder.R fails or is missing, the pipeline writes failed to run_history.csv, emails a failure alert (if configured), and exits — Clean, Upload and Reports never run. Every other step is soft: it logs a warning and the pipeline carries on with whatever data was already there.

Step 4 protects you from uploading a stale file

If Step 3 (Clean Geonames) failed, Step 4 skips itself by default rather than pushing yesterday's file to SharePoint under today's name — pass --force-upload if you want it to push the stale file anyway (e.g. Clean failed on a file lock, but the data itself is fine).

03Flags

--skip-lookup-refresh
Skip step 0 (refresh_preparedness_lookup.py) — reuse the existing data/lookup/lookup.xlsx.
--skip-fetch
Skip step 1 — reuse whatever's already in data/raw/.
--force-fetch
Passed to step 1 as --force-full; only matters if fetch isn't also skipped.
--skip-build
Skip step 2 (regional_im_repository_builder.R).
--skip-clean
Skip step 3 (clean_geonames.R).
--skip-upload
Skip step 4 entirely — nothing reaches SharePoint this run.
--force-upload
Upload anyway even though step 3 failed this run (pushes the previous, stale final file).
--skip-reports
Skip step 5 — all three report scripts together; you can't skip just one of them from here.
--upload-only
Standalone mode: ignores every other flag, runs only the SharePoint upload, then exits. Same as upload_only.bat.

Nightly Run & Failure Alerts

Mon–Fri, 23:00

This is the one project of the three set up for a fully unattended run — every weeknight it runs the entire pipeline above with no flags, and emails you if something breaks badly enough to matter.

01One-time setup

cmd.exe — run once
> setup_nightly_schedule.bat
# registers Task Scheduler job "IM Workflow Nightly": 23:00, Mon-Tue-Wed-Thu-Fri

You don't need to run this again unless you're changing the schedule or moving the project. It registers the task to run as you, while logged in — a locked screen is fine, but a sleeping or shut-down laptop at 11 PM means it silently doesn't run. Turn on "Wake the computer to run this task" under the task's Conditions tab in Task Scheduler (taskschd.msc) if you need it to survive that.

What runs at 23:00Detail
run_workflow_nightly.batRuns the full run_workflow.R (no flags — every step). Logs to logs\nightly_run.log in addition to run_workflow.R's own logs\workflow_<date>.log.

To test the schedule works without waiting for 11 PM: open Task Scheduler, find IM Workflow Nightly, right-click → Run, then check logs\nightly_run.log.

02Failure alerts

Alerts fire only on a genuine hard failure — Step 2 (Repository Builder) failing, or an --upload-only run failing — never on a soft/partial failure elsewhere in the chain, since those show up in run_history.csv and the dashboard instead without needing to page anyone.

ALERT_EMAIL_FROM
Sending Gmail address, set in config\secrets.env.
ALERT_EMAIL_TO
Where the alert lands.
ALERT_EMAIL_APP_PASSWORD
A Gmail App Password (not your normal password) — see config\secrets.env.example for how to generate one.

Leave any of the three blank and the pipeline itself is unaffected — you just won't be emailed about a failure until you next open the dashboard yourself.

Send a test alert by hand
$ python scripts\send_failure_alert.py --base-dir "C:\Users\TOURE\Documents\im_workflow" --subject "Test alert" --body "Just checking the email path works."
Two layers of alerting, so a crash can't go silent

run_workflow.R sends its own alert at the moment Step 2 (or --upload-only) fails. run_workflow_nightly.bat checks a marker file afterward (logs\last_alert_sent.flag) and only sends its own generic fallback alert if Rscript exited non-zero and that marker is missing — catching a crash severe enough that run_workflow.R never reached its own alert code at all (a missing R package, or Rscript failing to launch).
